Setting up the target in AWS
----------------------------
  git clone https://github.com/Gilc83/juice-shop.git && cd juice-shop
  docker build -t juice-shop-local-errors-fileupload .
  docker run -d --name Juiceshop-DetailedErrors-8130 --restart unless-stopped -p 8130:3000 \
      juice-shop-local-errors-fileupload

  - --restart unless-stopped is REQUIRED. Several requests in the scan end the Juice Shop process
    (the id22 and id50 findings). The local container comes back by itself because of this policy
    (it restarted twice during the gold run). Without it, the target stays down after the first crash
    and everything after it is lost.
  - Juice Shop rebuilds its database every time it starts, so a restart gives the scan a fresh
    application. The local scan restarts the container before it starts. In AWS, do the same
    (preRunCommand below, or by hand).
  - Any host or port works. The keys below compare paths with the origin stripped.

How to judge an AWS run against this file
-----------------------------------------
Compare SETS, never counts. Key each finding as (vulnerability id, METHOD, path, param, rule):
  - strip the origin from the path (several findings record an absolute URL such as
    http://localhost:8130/rest/chatbot/respond; in AWS it will carry the AWS host), and
  - normalise path templates: {__sileoVirtualParam1}, {id} etc. all compare as {id}.
Every finding in PARTS A-C shows its key in this form on its "Key:" line.

  Rule 1 (the gate): all 31 findings of PART A are present.
  Rule 2: id22 appears only on these five endpoints, any subset of them, each with confidence
          "confirmed" and a detail that describes the solo re-send:
            DELETE /api/Addresss/{id}     DELETE /api/Cards/{id}     PUT /rest/wallet/balance
            GET /api/Cards/{id}           POST /rest/basket/{id}/checkout
          Which of them convict varies from run to run. A conviction needs the application to die
          while exactly that request is in flight alone. A missing id22 endpoint is run variance, not
          a regression. This run convicted all five.
  Anything else needs an explanation before the run is called gold. The PART C extras already have
  one:
    - id50 DELETE /api/Addresss/{id} (Informative): deleting an address hits a foreign-key error,
      and Juice Shop ends its own process. The request is one the application's own feature sends,
      with no value changed. Also in the 2026-11-21 and 2026-11-22 gold runs.
    - id50 POST /rest/basket/{id}/checkout (Informative): an ordinary checkout, sent by the
      application's own frontend, also ends the process. Also in the 2026-11-22 gold runs.
    - id33 PUT /rest/wallet/balance [balance] (Informative, writes no rule): a NUL in the balance
      gets the application's own 404, so the application validates it. First seen in this run.

Known variance and host-dependent details
-----------------------------------------
  - Absolute URLs and the client IP inside Juice Shop's error page ("Blocked illegal activity by
    ::ffff:172.17.0.1") will differ in AWS. Only the keys matter.
  - /api/Challenges/ (A5, F014): the report can spell this path with or without the trailing slash.
    The reference holds one of the two spellings.
  - POST /rest/memories [image]: the gold finding is id13 Insecure File Upload (F019), plus id40 on the
    same endpoint (F035). Before 2026-11-13, runs sometimes reported id38 there instead of id13.
  - POST /api/Feedbacks/: the crawl usually answers the captcha wrong, so the recorded request is a
    401. id6 (F008, a NUL in captchaId answers 500 where every other probe answers 401) is measured
    against that refusal. id24 (F028) and id29 (F030) come from the stored-write coverage that revives
    the request from the captcha the application publishes.
  - The chatbot (/rest/chatbot/respond) findings depend on the conversation state, which makes them
    the most fragile members of the set. They are F002, F009, F020 and F027.
  - The crawl recycled its browser 3 times in this run (scope notes). That did not cost any finding.
  - Run time depends on the host. Locally the crawl plus fuzz took 3 h 07 m.
